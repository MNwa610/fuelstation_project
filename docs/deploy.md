# Развёртывание

## Выбор инфраструктуры

Для учебного проекта достаточно одного виртуального сервера и Docker Compose: база, API и статическая сборка клиента на одной машине. Это дешевле и проще, чем Kubernetes или отдельный serverless-контур. PostgreSQL остаётся в контейнере или ставится как управляемая БД у хостера — для защиты достаточно контейнера с томом.

В продакшене разумнее вынести Postgres на отдельный инстанс с бэкапами, а клиент раздавать через CDN. Для курсовой работы это избыточно.

## Настройка сервера

1. Арендовать VPS с Ubuntu, открыть SSH по ключу, отключить вход по паролю.
2. Установить Docker и плагин Compose.
3. Скопировать репозиторий, создать `.env` из примера (пароль БД, JWT_SECRET, ключ карт).
4. Запустить `docker compose up -d --build`.
5. Повесить Nginx или Caddy на хосте как обратный прокси с TLS (Let's Encrypt) на домен.
6. Клиент слушает порт 80 внутри сети и пробрасывается наружу; API — порт 3000. Снаружи лучше оставить только 80/443.

Миграции выполняются при старте контейнера server: `prisma migrate deploy`, затем seed, если администратор ещё не создан.

## Брандмауэр

На сервере открыть только 22 (SSH), 80 и 443. Порт PostgreSQL 5432 наружу не публиковать — к базе ходят соседние контейнеры по внутренней сети Compose. Учебный docker-compose для удобства пробрасывает 5432 и 3000 на localhost; на настоящей машине эти пробросы лучше убрать.

UFW-пример политики: запрет входящих по умолчанию, разрешить OpenSSH и Nginx Full.

## Мониторинг

Минимальный набор для учёбы:

- `docker compose ps` и `docker compose logs -f` — живы ли контейнеры.
- Эндпоинт `/health` — процесс Node отвечает JSON.
- Healthcheck Postgres в Compose (`pg_isready`) — сервер не стартует, пока БД не готова.
- При желании — бесплатный Uptime Kuma или простой cron с curl по `/health`.

Метрики CPU/RAM можно смотреть через `docker stats`. Полноценный Prometheus в рамки курсовой не обязателен.

## Healthcheck

- Контейнер db: `pg_isready`.
- Контейнер server: Node делает fetch на `http://127.0.0.1:3000/health`.
- Приложение: GET `/health` → `{ "status": "ok" }`. Это не проверка бизнес-логики, а проверка, что процесс слушает порт.
- Клиент Nginx отдаёт index.html; если API лежит, интерфейс откроется, но список заправок покажет ошибку — так и должно быть, слои независимы.
