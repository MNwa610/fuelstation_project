# Вопросы к защите (короткие ответы)

1. **Что это за проект?** Сайт, где видно заправки, остаток топлива и можно поехать по маршруту. Админ может поправить цифры.

2. **Почему JavaScript, а не TypeScript?** Так проще объяснять каждую строку на защите, без типов и сборок. Логика всё равно разделена по папкам.

3. **Зачем слои routes / controllers / services?** Маршрут знает только адрес. Контроллер только принимает запрос и отдаёт ответ. Вся работа с базой и правилами — в сервисе. Проще искать ошибки и писать тесты.

4. **Почему монолит, а не микросервисы?** Задача маленькая, одна база, один деплой. Микросервисы добавили бы сети и очереди без пользы для учёбы.

5. **Как считаете статус топлива?** Если литров ноль — OUT. Если меньше 15% бака — LOW. Иначе AVAILABLE. Считается на сервере, клиент только показывает.

6. **Что такое JWT?** Подписанная записка «этот человек — такой-то, роль такая-то». Браузер кладёт её в localStorage и шлёт в заголовке. Сервер проверяет подпись секретом.

7. **Почему пароль не лежит открытым?** Его хеширует bcrypt. Даже из базы нельзя прочитать исходный пароль.

8. **Чем USER отличается от ADMIN?** USER смотрит. ADMIN ещё меняет литры и цены и может запустить симуляцию. Чужой роль не подставит: её берём из токена, не из тела запроса.

9. **Что будет, если дернуть PATCH без токена?** 401. Если токен обычного пользователя — 403.

10. **Зачем FuelEvent?** Чтобы видеть, кто или что меняло остаток: человек (MANUAL) или суточная симуляция (SIMULATION).

11. **Как устроена симуляция?** Для каждой колонки случайно берём число машин и расход, вычитаем литры, не уходим ниже нуля, пишем событие. Раз в день по cron и по кнопке API.

12. **Почему фильтры на клиенте, а не в SQL?** Данных мало, код короче, карта и список фильтруются одним useMemo. Для тысяч АЗС фильтр лучше перенести на сервер.

13. **Как работает карта?** В HTML подключено API Яндекса. Ставим метки отфильтрованных АЗС. Клик ведёт на карточку. Геолокация браузера ставит синюю точку.

14. **Где ключ карт и секрет JWT?** В переменных окружения, не в git. В репозитории только .env.example с подсказками.

15. **Как поднимаете проект?** `docker compose up -d --build`. База, API и Nginx с собранным React. Либо локально: Postgres, migrate, seed, два npm run dev.

16. **Что проверяют тесты?** Регистрацию, логин с JWT, запрет PATCH без токена, успешный PATCH админом и появление записи в журнале.

17. **Почему Prisma?** Схема читается как список таблиц, миграции повторяются на любой машине, в коде нет сырого SQL.

18. **Это третья нормальная форма?** Да: сеть, тип топлива и остаток разнесены, нет повторения названия сети в каждой АЗС и нет истории, затирающей текущие литры.

19. **Как защищаете админку в интерфейсе?** Маршрут `/admin` смотрит роль. Это удобство. Настоящая защита — на сервере: без ADMIN изменение не пройдёт.

20. **Что бы сделали дальше?** Поиск ближайшей АЗС на сервере, график цен, уведомления «топливо кончилось», нормальная связь userId в журнале вместо комментария.
