# База данных

Используется PostgreSQL. Схема описывается в Prisma и применяется миграциями. Учебный объём данных: несколько сетей, десять АЗС в Москве, несколько типов топлива.

## Сущности

- **User** — пользователь. Email уникален. Хранится хеш пароля, не сам пароль. Роль USER или ADMIN.
- **Network** — сеть АЗС (Газпромнефть, Лукойл и т.д.).
- **Station** — конкретная заправка: имя, адрес, координаты, телефон, флаг активности, ссылка на сеть.
- **FuelType** — справочник видов топлива. Код уникален (AI92, AI95, DT).
- **StationFuel** — остаток и цена конкретного топлива на конкретной АЗС. Есть ёмкость и текущие литры, статус AVAILABLE / LOW / OUT.
- **FuelEvent** — журнал изменения остатка: тип MANUAL или SIMULATION, старые и новые литры, комментарий.

## Связи

- Сеть содержит много заправок (один ко многим).
- Заправка принадлежит одной сети.
- Заправка имеет много позиций StationFuel.
- Вид топлива используется на многих АЗС.
- Пара «заправка + вид топлива» уникальна: на одной АЗС нельзя завести два одинаковых сорта.
- У позиции топлива много событий журнала.

Пользователь в схеме не связан внешним ключом с FuelEvent: при ручном изменении в комментарий пишется идентификатор пользователя. Это упрощает учебный пример; в промышленной системе лучше сделать отдельное поле userId со связью.

## Индексы

- Уникальный индекс по email пользователя — быстрый вход и запрет дублей.
- Уникальный индекс по коду FuelType.
- Уникальный составной индекс StationFuel (stationId, fuelTypeId).
- Первичные ключи UUID. Внешние ключи на networkId, stationId, fuelTypeId, stationFuelId.

Для учебной выборки этого достаточно. Если заправок станут тысячи, имеет смысл добавить индекс по координатам и по статусу топлива.

## Нормализация

Данные приведены к третьей нормальной форме:

- Сеть не дублируется в каждой АЗС — вынесена в Network.
- Название топлива не копируется в каждую строку остатка — справочник FuelType.
- Остаток и цена зависят от пары «АЗС + тип топлива», поэтому живут в StationFuel, а не в Station.
- История не затирает текущие значения: текущее состояние в StationFuel, прошлые изменения в FuelEvent.

Это удобно объяснять на защите: нет повторяющихся «Газпромнефть» в десяти строках без справочника, нет цены АИ-95 «на всю заправку», если на колонках разные сорта.

## Безопасность данных

1. Пароль проходит bcrypt, в JSON-ответах поле passwordHash отбрасывается.
2. Секрет JWT и строка подключения к БД задаются переменными окружения, файл .env в git не попадает.
3. Изменять остатки может только роль ADMIN; без токена сервер отвечает 401, с ролью USER — 403.
4. Входные тела запросов проверяются Zod (email, длина пароля, неотрицательные литры).
5. Prisma использует параметризованные запросы, ручная склейка SQL не применяется — это снижает риск SQL-инъекций.
6. Клиент ходит к API по HTTPS в реальном деплое; в Docker для учёбы используется HTTP на localhost.
