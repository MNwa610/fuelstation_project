# Требования

## Цель системы

Сервис помогает водителю увидеть, на каких АЗС Москвы есть нужное топливо, сколько его осталось и как доехать. Администратор сети может поправить остатки вручную. Учебная симуляция раз в сутки уменьшает литры, как будто за день проехали машины.

## Функциональные требования

1. Гость видит список активных заправок с сетью и статусом топлива.
2. Гость видит заправки на карте и открывает карточку по клику на метку.
3. Гость фильтрует список по типу топлива, статусу, фрагменту адреса и радиусу от своей геопозиции.
4. На карточке АЗС показаны адрес, телефон, цена, остаток в литрах и статус каждого вида топлива.
5. С карточки можно открыть маршрут в Яндекс.Картах.
6. Пользователь регистрируется (email, пароль не короче 6 символов, имя) и входит в систему.
7. После входа выдаётся JWT на 7 дней. Пароль в ответах API не возвращается.
8. Администратор изменяет остаток, цену и статус топлива. При изменении литров статус пересчитывается: нет литров — OUT, меньше 15% ёмкости — LOW, иначе AVAILABLE.
9. Каждое ручное изменение пишет событие FuelEvent типа MANUAL.
10. Симуляция для каждой позиции топлива генерирует расход (0–30 машин, 5–40 литров на машину), не опускает остаток ниже нуля, пересчитывает статус и пишет FuelEvent типа SIMULATION.
11. Симуляция запускается раз в сутки по расписанию и может быть запущена администратором вручную.
12. Страница админки доступна только роли ADMIN. Пользователь с ролью USER получает отказ.

## Нефункциональные требования

1. Понятный код на JavaScript: слои routes → controllers → services, чтобы студент мог объяснить каждую строку.
2. Время ответа списка заправок на учебной выборке (десятки АЗС) — в пределах одной-двух секунд.
3. Пароли хранятся только как хеш bcrypt. Секрет JWT не кладётся в git.
4. Интерфейс работает в актуальном Chrome/Firefox, вёрстка читаема на ширине ноутбука и телефона.
5. Система поднимается командой docker compose. Есть проверка живости `/health`.
6. Ошибки API — JSON с полем error и понятным HTTP-кодом (400, 401, 403, 404, 409, 500).

## Варианты использования

### UC-1. Водитель ищет АИ-95 рядом с собой

1. Водитель открывает главную страницу.
2. Нажимает «Моё местоположение», браузер спрашивает разрешение.
3. Выбирает тип топлива «АИ-95» и радиус, например 5 км.
4. На карте и в списке остаются только подходящие АЗС.
5. Открывает карточку, смотрит цену и остаток, нажимает «Проложить маршрут».

### UC-2. Новый пользователь регистрируется

1. Пользователь открывает «Войти», затем регистрацию.
2. Вводит имя, email и пароль.
3. Система создаёт учётную запись с ролью USER.
4. После входа токен сохраняется в браузере, открывается список заправок.

### UC-3. Администратор правит остаток

1. Администратор входит как ADMIN.
2. Открывает «Админка».
3. Меняет литры у выбранного топлива и нажимает «Сохранить».
4. Сервер пересчитывает статус и создаёт событие MANUAL.
5. На публичной карточке АЗС водитель видит новые цифры.
