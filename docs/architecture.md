# Архитектура

## Что сделано

Один монолит: один процесс Express, одна база PostgreSQL, один React-клиент. Внутри сервера код разрезан на слои, но это не отдельные сервисы по сети, а папки в одном репозитории.

Поток запроса: маршрут принимает URL и вешает middleware → контроллер читает req и вызывает сервис → сервис считает правила и ходит в Prisma → ответ уходит через контроллер. Ошибка бросается как исключение и ловится в общем обработчике.

Клиент — SPA на Vite. Состояние пользователя — простой React-контекст и localStorage с JWT. Списки фильтруются в браузере.

## Монолит

Плюсы для этой задачи: одна база — транзакция «обновить литры и записать событие» делается без распределённых соглашений; один деплой; студенту проще поставить отладчик и пройти запрос глазами; меньше сетевых сбоев между кусками системы.

Минусы: нельзя масштабировать только «тяжёлую симуляцию» отдельно от API логина; команда из десятков человек будет мешать друг другу в одном репозитории. Для курсового объёма минусы не важны.

## Сравнение с микросервисами

Микросервисы разрезали бы систему на «пользователи», «заправки», «симуляция», каждый со своей базой. Плюс — независимый деплой и изоляция сбоев. Минус — нужны очереди, согласованность данных, больше Docker-сервисов, сложнее защита и отладка. Учебная нагрузка (десятки АЗС, редкий cron) не создаёт такого трафика, чтобы оправдать эту цену.

Симуляция могла бы быть отдельным воркером. В монолите её держит node-cron в том же процессе. Если процесс ляжет, cron тоже встанет — для учёбы это приемлемо и честно объясняется.

## Сравнение с serverless

Serverless (функции по HTTP, база как услуга) хорошо подходит для редких всплесков и оплаты «за вызов». Минусы: холодный старт, лимиты времени (долгая симуляция по всем АЗС может не уложиться), сложнее держать постоянное TCP-соединение Prisma, труднее отлаживать локально без облачного аккаунта.

Для вуза serverless привязывает сдачу к конкретному облаку и ключам преподавателя. Docker Compose на ноутбуке воспроизводится без карты.

## Почему слои внутри монолита

Слои — это дисциплина, а не микросервисы. Контроллер не пишет SQL, сервис не ставит заголовки HTTP, маршрут не считает литры. Это упрощает тесты: Supertest бьёт в HTTP, сервисы можно читать как обычные функции. Преподаватель может спросить «где считается статус?» — ответ один: функция расчёта статуса и сервис топлива, не файл маршрутов.
